# frame-parser · 多进制 / 多帧格式 数据帧解析器

> **English** — Frame Parser is a PyQt6 desktop tool and CLI for decoding binary data frames
> from serial, CAN, MQTT or log captures. It accepts HEX/DEC/BIN/ASCII input, supports six
> framing modes and nine checksum algorithms, lets you define fields or analyze raw bytes, and
> provides a per-frame data table with per-column statistics, plots, spike detection and
> two-way source highlighting. A 406-case headless self-test is included. Licensed under MIT.

一个 PyQt6 写的通用「多进制 / 多帧格式」数据帧解析工具：**输入随便贴什么进制、帧格式随便换、字段随便加换算函数**，
专门用来现场调试串口 / CAN / MQTT 上报的二进制数据帧。整体**黑白（单色）主题**。

核心能力：多进制输入 → 6 种分帧方式 + 9 种校验 → 字段定义 → **一帧一行的数据表 + 按列分析**
（统计 / 曲线 / 突变 / 字节规则）→ 表格 ↔ 原文双向定位 → 命令行批处理。

## 项目定位

`frame-parser` 面向「手上只有一段抓包、没有协议文档、协议随时会改」的现场调试场景：
不需要写代码或格式描述文件，在界面里点几下就能换进制、换帧格式、试校验、加换算函数，
把二进制流变成一张能统计、能画曲线、能点回原文逐字节核对的表。

GUI、命令行（`cli.py`）、自检（`selftest.py`）和导出共用同一套解析引擎（`app/`），
同样的输入在三种入口得到同样的结果；界面基于 PyQt6，自检走 Qt offscreen，不需要显示器。

## 安装

环境：Python 3.9+；界面依赖 `PyQt6>=6.5.0`（见 `requirements.txt`），Windows / Linux / macOS 通用。

```bat
python -m pip install -r requirements.txt
```

Windows 下也可以直接用 `run.bat`：自动找 Python，缺 PyQt6 时自动安装，然后启动界面。
Linux / macOS 用 `python main.py`（Qt 需要系统图形库，按平台装好 PyQt6 依赖即可）。

验证环境（不需要显示器）：

```bat
python selftest.py     :: 406 项无界面自检，退出码 0 即全部通过
```


   工具会按换行/行长或自相关找出帧长、帧头、长度字段语义、校验算法，并给出置信度。
3. **看数据**：右边「**数据表分析**」= **一帧一行 × 一列一个字段/字节**，
   右侧给出每列的 有效/范围/均值/中位数/σ/不同值/变化次数/趋势/最大跳变；点列标题看曲线与突变清单。

6. **对着原文核字节**：在任意表格里点一个格子/整帧 → 左侧输入框自动**滚到那里并反色选中**；
   反过来在原文里选中一段 → 帧列表跟着定位。

## 二、输入：随便哪种进制

| 进制 | 支持的写法 |
|---|---|
| HEX | `AA 55 01`、`AA5501`、`0xAA,0x55`、`1Ah`、每行一帧 |
| DEC | `170 85 1 2`，可指定每值占 1/2/4 字节与字节序 |
| BIN | `10101010 01010101` |
| ASCII | `$POS,01,...\r\n`，支持 `\r \n \t \0 \xNN` 转义 |
| 自动识别 | 多行输入按"逐行投票"取多数，所以日志里夹着注释行也不会认错 |

坏行（注释行、表头行）会被跳过并计入警告；例如 `backward_sample.txt` 第一行的
`=== field capture sample ... ===` 不会影响后面 12663 帧的解析。

**选中一段就报"多少字节 + 各进制值"**：在输入框里选中内容后，下方信息栏显示
`选中 8 字符 = 3 字节 │ HEX: AA 55 01 │ DEC: 170 85 1 │ BIN: 10101010 … │ ASCII: …`；
表格里选中若干格/若干行也报同样的信息（字节对照表与位编辑器会额外给出选中多少字节、
单字节时还列出 b7~b0 位组成）。输入区还有「复制选区 HEX / 复制选区 BIN」两个按钮。

## 三、样本数据（data 目录）

「文件 → 样本数据」直接列出 `data/` 里的文件点开即用；
「选择样本目录…」可以指向自己的日志目录（例如 `logs`）。
打开某个样本时，如果某个预设就是照着它做的（`Preset.sample_file` 同名），
会**自动套用该预设的分帧设置与字段表**，不会再出现"数据是 EB 90、字段还是 AA55 预设"的错配。

**预设 ⑧** 就是按现场采集样本 `backward_sample.txt` 做的：

| 位置 | 含义 |
|---|---|
| 0~1 | 帧头，恒定 `EB 90` |
| 2 | 帧长 = 总长 - 5（值 151，总长 156） |
| 5 | 报文类型，恒定 `0x92` |
| 7 | 帧计数，逐帧 +2（可用来判断丢帧） |
| 8~64 | 数据区 |
| 65 / 73 / 81 / 89 | 4 组 8 字节通道数据（数值逐帧小幅变化，疑似 4 路测距/角度） |
| 153 | 尾部标志（逐帧变化，可用「试算校验」确认是否校验字节） |
| 154~155 | 帧尾，恒定 `5B BF` |

该样本 12663 帧全部 156 字节，用「定长帧 156」分帧，8 个字段一次解析到位。

## 四、自动推断分帧参数（Ctrl+I）/ 智能识别帧格式

协议未知时的第一步。两个入口：

* **「分帧设置」里的「智能识别帧格式」按钮** —— 一键把帧格式配好（优先级见下）；
* **工具栏「自动推断分帧参数…」（Ctrl+I）** —— 给出一份候选列表让你挑，带置信度与详细说明。

判定优先级：

1. **一行一帧**（日志最常见）：逐行数出每行多少字节 —— 行长一致就直接按「定长帧 N」切；
   行长不一致（或本来就是文本行）就改成**按换行分帧**（自动识别 `\r\n` / `\n`）；
2. **自相关找周期**：按周期整数倍采样，比较相邻帧同一位置的字节，找出帧长；
3. **定位帧头相位**：在周期内搜偏移，找出每个周期起点都一致的前缀 → 真正的帧头（前导字节自动跳过）；
4. **还原长度字段**：试 偏移 0~8 × 1/2/4 字节 × 大小端 × 两种语义，看哪个能让「长度值 == 帧间隔」；
5. **试算校验**：把推断出的帧喂给 9 种校验算法，给出匹配帧数；
6. **恒定/变化字节**：列出跨帧不变的字节位置（帧头、类型、保留位、帧尾），
   其中数值接近帧长的会被标为「疑似长度字段」。

结果是一份带置信度和说明的候选列表，双击即可应用。命令行里用 `--infer` 打印同样内容。

实测：现场样本 `backward_sample.txt` → **定长帧 156 字节（帧头 EB 90），置信度 99%**
（智能识别还会直接说出理由：「共 12664 行，行长分布 156 字节×1999…… 每行都是 156 字节」）；
AA55 预设样本 → **帧头 AA 55 + 2 字节长度字段（偏移 2，大端）+ CRC16/MODBUS，置信度 100%**。

抓包文件前面有时间戳/前导数据时，用「分帧设置」里的「跳过前 N 字节」（推断也会自动给出）。

## 五、位编辑器（点位翻转）

右侧「位编辑器」页签：一帧一表，`偏移 / HEX / DEC / b7…b0`，每个位是一个复选框，点一下就翻转。

* 改完自动重算校验（按当前分帧设置里的算法与位置），校验状态实时显示 ✓/✗；
* 被修改的字节整行灰底标记，方便和原始值对照；
* 列标题右键 → 「快捷操作」：`b7 整列置 1 / 清 0 / 取反`、`本列全部取反`、`恢复原始值`；
* 结果可「复制结果 HEX」「保存为 .bin」「设为输入数据（仅此段）」——后者立刻重新解析，看字段值怎么变。

用途：没有协议文档时改一个位看下游变化，反推这个位的含义；或者手工修一帧数据再发出去。

## 六、从日志提取数据帧（Ctrl+E）

现场抓包往往不是纯字节流，这个功能直接把日志变成"一行一帧"的可解析数据：

| 日志格式 | 选哪条规则 |
|---|---|
| `{"can_id":"0x1E7","dlc":8,"data":"ea07071900000000","ts":...}` | JSONL/JSON 的 data 字段 |
| CAN 分析仪 CSV：`...,0x0021,数据帧,标准帧,0x08,x\| 00 00 02 00 64 1C 00 00` | CAN 分析仪 CSV 数据列 |
| 其它日志里的引号内 HEX / `0xAA 0x55` 序列 / 裸 HEX 串 | 对应规则，或自己写正则 + 捕获组 |

* **行过滤**填 `0x1E7` 就只提取这一路 CAN ID 的报文；点「统计 ID」会列出日志里出现过的 can_id。
* 导入 `.jsonl` / `.csv` 时会**自动挑规则提取**，避免把几十万行原始日志塞进输入框；读取上限默认 8 MB（可调）。

## 七、分帧：6 种帧格式

| 方式 | 参数 |
|---|---|
| 帧头 + 长度字段 (+校验) | 帧头、长度字段偏移/字节数/字节序、长度值是否含帧头、是否含校验 |
| 定长帧 | 每帧字节数 |
| 长度前缀 + 数据 | 前缀 1/2/4 字节、字节序、是否包含自身 |
| 分隔符分帧 | 分隔符 HEX（`0D 0A`、`7E`…）、是否算在帧内 |
| TLV | Tag 字节数、Len 字节数/字节序（每个 TLV 拆成一帧） |
| 整包不拆分 | 单帧，仍可做帧尾校验 |

## 八、校验算法

SUM8、取反 SUM8、SUM16、XOR8(BCC)、CRC-8(0x07)、CRC-16/MODBUS、CRC-16/CCITT-FALSE、
CRC-16/XMODEM、CRC-32，均带标准校验值自测（CRC16/MODBUS 对 `123456789` = 0x4B37）。

> 不知道对端用的是哪个算法？点「试算校验算法」，把所有算法 × 大小端都试一遍并按匹配帧数排序。

## 九、字段定义

`字段名 / 类型 / 偏移 / 长度 / 字节序 / 系数 / 偏置 / 单位 / 位域 / 显示进制 / 表达式 / 备注`

* **长度填 0 = 取到帧尾**（变长字段，例如 TLV 的 Value、ASCII 整行）
* 类型：无符号整数、有符号整数、浮点(4/8B)、Bool、BCD(自动忽略 0xF 空位)、ASCII、原始字节、表达式
* 系数/偏置：`工程值 = 原始值 × 系数 + 偏置`（如 `1234 × 0.1 = 123.4 km/h`）
* 位域：`0`、`3-5`、`4:6`
* 表达式字段可引用前面字段名（含中文名）：`航向密位 = 航向 * 16.6667`

| 悬停提示 | 停在任意数值格子上：原始值、换算函数、换算结果、HEX/DEC/BIN/ASCII/U32/I64 |
| 复制 | Ctrl+C 复制选区；右键可复制单元格 / 悬停信息 / 整行 / 整列 |
| **跳到原文** | 在任意表格里选中格子/整列/整帧 → 左侧「输入数据」自动**滚动到对应字节并反色选中** |
| **反向定位** | 在左侧输入框里选中一段 → 「帧列表」自动跳到对应帧 |

**双向定位**是怎么对上的：解析时顺带记录"每行文本 ↔ 每行字节"的区间（`codec.LineSpan`），
所以点到某个字段/某个字节时，能精确算回它是原文里的哪两位十六进制。举几个实测例子：

| 在表格里点 | 左侧反色选中的内容 |
|---|---|
| 分析表「帧尾」字段（帧#100） | `5B BF`（正是该帧尾部两字节） |
| 分析表字节列「偏移 103」（帧#21） | `00`（精确到那两位） |
| 帧列表第 5 行（整帧） | 该帧整行的 156 字节文本（467 个字符） |
| 左侧选中第 301 行的内容 | 帧列表跳到第 301 行（帧 #300） |

反色用的是主题里的"黑底白字"，输入框失焦时也保持这个配色，方便一边看表格一边对照原文。

换算函数里 `v` 就是该格原始值，可用 `abs/round/min/max/pow/int/float/sqrt/log/sin/cos/atan2/hex/bin`
和常量 `pi/e`；设置了换算函数的列，标题会带 `⚙` 标记。

例：`v * 0.1`（×0.1）、`v / 1000`（÷1000）、`v - 40`（偏置）、`(v >> 4) & 0xF`（取位）、
`v * 360 / 65536`（编码器→度）、`v * 180 / pi`（弧度→度）。

## 十一、进制视图

整段数据或选中帧**整体转 HEX / DEC / BIN / ASCII**：可调每行字节数、分隔符、大小写、`0x` 前缀、
偏移列、ASCII 附列；下面「字节对照表」逐字节并排给出 `偏移 / HEX / DEC / BIN / 字符 / b7~b0`，
每个位都是独立一列（可以只给 b7 这列上色，一眼看出标志位）。
「复制为」可导出 HEX 文本、C 数组、Python bytes、Python 列表、十进制数组、二进制、hexdump、Base64。

## 十二、命令行模式（cli.py / cli.bat）

```bat
cli.bat --list-presets                       :: 列出内置预设
cli.bat --list-modes                         :: 列出分帧方式与校验算法
cli.bat --infer --file data\backward_sample.txt
cli.bat --preset backward_eb90 --file data\backward_sample.txt --limit 20
cli.bat --preset backward_eb90 --file data\backward_sample.txt --frame-range 500-1500   :: 只看这一段帧
cli.bat --preset backward_eb90 --file data\backward_sample.txt --every 100 --only-fail   :: 抽样 + 只看失败帧
cli.bat --preset aa55_crc16 --file data\aa55_crc16.bin --format csv --out frames.csv
cli.bat --probe --file data\fixed_xor8.bin --mode fixed --fixed-len 10
cli.bat --auto-extract --file logs\sample.jsonl --extract-filter 0x1E7 ^
        --mode fixed --fixed-len 8 --out can_1e7.csv
```

* 数据来源：`--file`（`.bin/.dat/.hex` 按二进制读，其它按文本读并自动识别进制）/ `--text` / `--stdin`
* 分帧参数：`--mode`、`--fixed-len`、`--header`、`--len-offset/-size/-order`、`--len-no-header`、
  `--delimiter`、`--prefix-*`、`--tag-size`、`--skip-bytes`、`--checksum/-order/-where`
* **行规则**（挑哪些帧，帧号同界面「帧#」，从 0 开始，`-1` = 最后一帧）：
  `--frame-range 500-1500`（也支持 `1000-` 到末尾、`-500-` 最后 500 帧）、`--every 100`（每 100 帧取 1 帧）、
  `--only-fail`、`--only-ok`；筛选在分帧之后立刻完成，后面的表格 / JSON / CSV / 二进制导出**全都按筛完的帧算**，
  并打印一行 `[行规则] 帧 500 ~ 1500（共 1001 帧） → 保留 1001 / 12663 帧（去掉 11662 帧）`
* 帧数上限：`--max-frames N`（或 `--limit N`）限制单次分帧多少，`0 = 不限`（默认）；
  `--read-mb 0` 表示读整个文件（默认只读前 8 MB，128 MB 抓包要写 `--read-mb 0`）
* 字段：`--fields 字段.json`（界面「导出字段 JSON」生成），或用预设自带的
* 输出：`--format table|json|csv|hex|hexdump|bin|summary`、`--csv-mode frames|fields`、`--out 文件`
* 退出码：**0** 成功 / **1** 出错（含 `--frame-range` 写法错误）/ **3** 解析成功但有帧校验失败（方便卡在脚本里）
* 常用：`--limit N`（最多几帧）、`--quiet`（只输出结果，不打印日志）

## 十三、数据表分析（一帧一行 · 按列分析）

右侧「**数据表分析**」页签就是这张表：**一行 = 一帧，一列 = 一个字段（或一个字节）**。

| 区域 | 内容 |
|---|---|
| 左：数据表 | `帧# / 偏移 / 长度 / 校验` + 各字段列（或各字节列），值按该字段的显示进制/换算函数渲染 |
| 右：每列统计 | 字段 / 类型 / 有效（含空值数）/ 范围 / 均值 / 中位数 / σ / 不同值 / 变化次数 / 首→末 / 首末差 / 趋势 / 最大跳变 |
| 右下：曲线 | 点列标题（或统计表里的一行）→ 该列随帧号变化的折线图，突变点用空心圈标出 |
| 右下：突变清单 | 该列所有突变帧：`帧 6：254 → 0（Δ -254）` |

工具栏：`列模式`、`列规则…`（配列 = 看哪些字节）、`行规则…`（配行 = 看哪些帧）、
`突变阈值 Nσ`（默认 4σ）、`只看异常帧`、`字段列 ▾`、`字段模板 ▾`、`重算统计`、`导出宽表 CSV`、`复制统计`。

> **表格没有"最多多少帧"这回事**：行数就等于帧数（行规则筛出来多少就是多少），
> 表格是**滑动窗口** —— 滚到哪算哪、填哪；初始只铺 2 万行，滚到底自动续（2 万 → 4 万 → 16 万 → 全量），
> 视口外的行随时可以按需算出来（导出、复制、定位都按需取，不受"滚过没滚过"影响）。

### 两种列模式

| 模式 | 列是什么 | 用途 |
|---|---|---|
| **自定义列（规则）** | 4 个基础列 + **按「列规则」生成的列** | 不用写字段定义，自由决定看哪些字节 / 哪些数值 |
| 字段列（按字段定义） | 4 个基础列 + 每个字段一列 | 已定义字段，按语义分析 |

字段表是空的（或只有 1 个字段）时**自动切到自定义列**，打开就能看到整帧。

### 列规则（点「列规则…」弹小窗口）

一个弹窗里可以叠加**多条规则**，每行一条：

| 字段 | 含义 |
|---|---|
| 列名 | 列标题前缀（如 `偏移`、`四通道`） |
| 起始偏移 | 从帧内第几个字节开始 |
| 列数 | 生成多少列 |
| 步长 | 每列跨多少字节（0 = 按「每列字节」紧排） |
| 每列字节 | 1/2/4/8 —— 大于 1 时按字节序**合成一个数值列** |
| 字节序 | 大端 / 小端（多字节列才有意义） |
| 显示进制 | HEX / DEC / BIN / ASCII（之后还能右键整列改，也能加换算函数） |
| 偏移列表 | 直接挑列，如 `0,1,2,8-15`（填了就忽略起始/列数/步长） |

对话框带**实时预览**（会生成多少列、列名是什么、有没有越界或超上限），
以及「常用规则 ▾」一键套用：前 16 字节、整帧 64 列、每 2 字节大端 int16、每 4 字节小端 int32、
指定偏移列表、字节 + 数值两条规则叠加。**规则随配置一起保存/恢复**。

举例（`backward_sample.txt`，3 条规则 → 16 列）：

```
规则1  偏移 ：从 0 起 8 列，每列 1 字节，HEX      → 偏移 0 = 235 │ 偏移 1 = 144 │ …
规则2  u16  ：从 0 起 3 列，每列 2 字节大端，DEC  → u161 @0 = 60304 │ u162 @2 = 38656 │ …
规则3  四通道：从 65 起 4 列，每列 2 字节小端     → 四通道1 @65 = 56384 │ 四通道2 @67 = 4780 │ …
```

每条通道、每个 int16/int32 都能直接按列看统计/曲线/突变，不用先写字段定义。

### 行规则（点「行规则…」弹小窗口）—— 决定看哪些帧（哪几行）

**列规则管"看哪些字节"，行规则管"看哪些帧"**，两个弹窗长得一样、用法也一样，可以叠加多条、可以「且 / 或」。

帧号就是表格「帧#」列里的数字，**从 0 开始**，`-1` 表示最后一帧 —— 所以「起始 0 / 结束 -1」= 全部帧。

| 规则类型 | 填什么 | 例子 |
|---|---|---|
| **帧号区间** | 起始帧、结束帧（可负数，从末尾数） | `0 ~ 499`（前 500 帧）、`500 ~ 1500`、`1000 ~ -1`（从第 1000 帧到末尾）、`-500 ~ -1`（最后 500 帧） |
| **采样（每 N 帧取 1）** | 每N帧、相位 | `每 10 帧取 1` —— 12663 帧变 1267 帧，看长程趋势不卡 |
| **帧内字节比较** | 帧内偏移、比较、数值、取几字节（含大端/小端） | `帧内 [2] > 150`、`帧内 [0..1] big != 0xEB90` |
| **校验状态** | 失败 / 通过 / 未启用 | `校验状态 = ✗ 失败` —— 只看坏帧 |
| **帧长比较** | 比较、数值 | `帧长 != 156` —— 抓异常长度的帧 |
| **帧内包含内容** | 包含 / 不包含 + 内容 | 内容写 `EB 90` 或 `ascii:SPD`、`'$GNGGA'` |

弹窗特性：

* 每行一条规则，列是「启用 / 规则 / 起始帧 / 结束帧 / 每N帧 / 相位 / 帧内偏移 / 比较 / 数值 / 取几字节 / 校验状态 / 内容 / 说明」，
  **只有该规则用得上的格子能编辑**（其余置灰），说明列实时写成中文句子；
* 顶部选**多条规则的组合方式**：`同时满足（且）`= 交集，`满足任一（或）`= 并集；
* 底部**实时预览**：`命中 201 / 12663 帧（1.59%）　例：500, 505, 510, 515, 520, 525 … 1490, 1495, 1500`；
  命中 0 帧时直接警告「没有任何帧命中，表格会是空的」，不会让你对着空表发呆；
* 「常用规则 ▾」一键套用 14 种常用组合（全部帧 / 前 500 帧 / 帧 500~1500 / 从第 1000 帧到末尾 / 最后 500 帧 /
  每 10 帧取 1 / 每 100 帧取 1 / 只看校验失败 / 只看校验通过 / 只看定长 156 帧 / 帧长异常（≠156） /
  第 0 字节 ≠ 0xEB / 第 2 字节 > 150 / 帧号区间 + 每 5 帧取 1 两条规则）；
* 应用后按钮旁显示 `（命中 201/12663 帧）`，悬停看完整规则说明；**规则随配置一起保存/恢复**。

**行规则的筛选结果同时作用于表格、统计、曲线、突变检测**：

```
共 12663 帧 │ 行规则命中 201 帧（1.59%） │ 统计基于筛选后的 201 帧 │ 表格显示前 201 行 │ 字段列 8 个
```

也就是说：选「帧 500~1500」之后，统计的含义就是"这 1001 帧的统计"，曲线的横轴、突变清单里的
`帧 1500：…` 也都是真实帧号，不会混进区间外的帧。`只看异常帧` 是在行规则之后再叠一层过滤。

* 字节列的**恒定值直接写进列标题**（如 `偏移 5 = 146`），变化的列标 `（N 种取值）`；
* **统计按全部帧（或行规则筛出来的帧）算**，不受表格显示行数限制，信息栏写明
  `共 12663 帧 │ 统计基于全部 12663 帧 │ 已铺 20000 行，滚到底自动续（共 12663 行）│ 规则 2 条 → 12 列（偏移 0~72）`；
* `字段模板 ▾` 可一键套用某个预设（含现场样本预设）的字段定义，列数立刻跟着字段数变。

<details>
<summary>示例：不定义任何字段，直接分析 <code>backward_sample.txt</code></summary>

```
列: 帧# | 偏移 | 长度 | 校验 | 偏移0=235 | 偏移1=144 | 偏移2=151 | 偏移3=0 | … | 偏移15
行:  0 |    0 |  156 |  —  |   EB     |    90    |    97    |    00   | … |   B3
```

* 列格式（HEX/DEC/BIN）、列颜色、列换算函数、悬停多进制提示**与其它表完全一致**——
  给"车速"列加 `v*0.1`，表里显示的立刻就是工程值；
* **点表格里的格子 → 左侧原文反色定位**（见第十节的"双向定位"），
  一眼看清这个值对应原文的哪两位十六进制；
* 表是按需生成（切到本页签才算）且流式分片渲染的，几万帧也不卡。

典型流程：看统计表找"变化次数多 / σ 大 / 最大跳变离谱"的列 → 点它看曲线 →
用突变清单定位帧 → 点那一格跳回原文核对字节 → 需要细看就切「位编辑器」。

## 十四、调试辅助

* **自动解析**：输入即解析（可关），F5 立即解析；按脏标记只重算受影响的那一段
* **智能识别帧格式**：「分帧设置」里的按钮 —— 一行一帧就按行长设定长、行长不一就按换行分帧、
  否则自相关找帧长与帧头（详见第四节）
* **错配提醒**：分不出帧、整段只分出 1 帧、或所有帧校验都失败时，日志页与状态栏会明确提示，
  并建议用「自动推断分帧参数」(Ctrl+I)——避免拿 A 协议去套 B 数据却看不出问题；
  字段表只有 1 个字段时也会提醒「数据表分析的列就是字段」
* **校验失败可查因**：校验列显示 ✗ 的格子，鼠标悬停直接给出
  `校验失败：计算值 FB 6E ≠ 帧内 5B BF`，一眼分清是算法选错还是数据坏了
* **文本列不被进制污染**：原始 HEX / 摘要 / 备注这类文本列永远原样显示；
  只有数值列才会套用「本列显示格式」，不会把 `EB 90` 显示成 `235 144`
* **表格 ↔ 原文双向定位**：点表格里的值跳回左侧原文并反色选中；原文里选中一段 → 帧列表定位（见第十节）
* **跟随文件**：选中日志/抓包文件后实时刷新（读尾部 512 KB），边跑边看
* **试算校验算法** / **自动推断分帧参数**：逆向未知协议的两把钥匙
* **位编辑器**：改一位看一位
* **日志提取**：正则 + 行过滤 + can_id 统计
* **帧筛选**：全部 / 仅校验失败 / 仅校验通过 / 仅不完整帧 + 关键字过滤（帧列表页）；
  想按帧号、采样、帧内字节、帧长挑帧就用分析页的「**行规则…**」（见第十三节）
* **字段异常清单**：越界、类型不符的字段灰底黑字标出，日志页给汇总
* **帧数一眼可见**：工具栏最左边固定显示 **`共 12663 帧`**（黑底白字方框）+ `× 156 字节/帧`，
  切到哪个页签都在；状态栏右侧还有 `帧 12663`、`输入 1968156 字节`、`校验 ✓0 / ✗0`、`耗时 0.51 ms`，
  帧列表信息栏写 `共 12663 帧`（表格=滑动窗口），分析页信息栏写 `共 12663 帧 │ …`；
  **帧数在分帧一做完就显示**，流式解析过程中还在长时会补一句 `已出 N`，
  悬停工具栏帧数可看「一共解析出多少帧 / 共多少字节 / 帧长恒定还是几种 / 校验 ✓✗— 各多少」
* **统计**：字节数、帧数、校验通过/失败、解析耗时、输入/分帧/字段三类异常
* **导出**：解析结果 JSON、字段表 CSV、帧列表 CSV、宽表 CSV、配置 JSON（含列样式、列规则与行规则）
* **现场保存**：退出时自动记住布局、列颜色/格式/换算函数、分帧设置、字段表、输入数据、列规则与行规则

### 大文件性能（实测 128 MB 现场抓包 = 287,482 帧 × 156 字节）

大文件自动走「**mmap 分页 + 流式解码分帧 + 按需取字节**」（见第十五节后半），内存不再随文件增长：

| 操作 | 结果 |
|---|---|
| 导入 + 建行索引 + 解析 + 首屏 | **0.8 秒** |
| 改分帧参数后重新解析（128 MB / 28.7 万帧） | **3.0 秒**（其中流式解码 + 索引分帧 0.9 秒） |
| 表格里点一个格子 / 点一行 | **9 ~ 10 毫秒** |
| 表格 → 左侧原文定位（**自动翻到那一页并反色选中**） | **8 ~ 10 毫秒** |
| 编辑器翻页 / 跳到指定行 | **9 毫秒** |
| 分析页按列统计（默认统计上限 5 万帧，分片推进） | **0.35 秒**，不再卡住界面 |
| 分析页只在「行规则」窗口内统计（5000 帧） | 0.1 ~ 0.3 秒 |
| 内存 | **私有提交 143 MB**（含 PyQt6 自身约 60 MB）；工作集 291 MB，其中大头是系统可回收的 mmap 文件页 |

优化前，同样是这份数据：点一个格子 **1.4 ~ 5.3 秒**、重新解析 **30 ~ 49 秒**、内存 **700 ~ 800 MB**。

其中一件关键修复：**点表格时的定位原来是"整篇重算"**。
`QPlainTextEdit.toPlainText()` 在 128 MB 文档上一次要 0.6 秒，而一次点击要调它两次
（还顺带整篇解码、整篇自动识别进制）→ 点一下就卡 1.4~5 秒。现在：

* 用 `QTextDocument` 块随机访问**只取那一行文本**（`doc.findBlock()`，O(log n)，实测 0.0 ms）；
* 选区 → 字节数改成**二分 + 行内数字计数**（原来把几万条行区间整个遍历一遍）；
* 解析完成后把"总字节数 / 实际进制"回填进输入面板（`set_parsed_info`），不再为显示几个数字整篇解码；
* 同一个格子重复选中只定位一次（整列选择会连发好几次 `selectionChanged`）；
* 表格 → 原文 定位时不再反过来触发一次"原文 → 表格"；
* 工具栏帧数的"帧长分布 / 总字节 / 校验数"按分帧结果**记忆化**（原来每个数据块都重扫 28 万帧，
  仅这一项就让 128 MB 的重新解析从 3 秒变成 30 秒以上）。

### 大文件模式：分页 + 按需读取（不把整份数据装进内存）

超过 4 MB 的**文本**文件会自动切到"大文件模式"（粘贴/小文件仍走原来的内存路径，行为不变）：

| 环节 | 做法 |
|---|---|
| 行索引 | 文件用 `mmap` 打开，扫一遍换行符记下每行起始位置（`array('q')`，28 万行约 2.3 MB，0.15 秒） |
| 解码 + 分帧 | **流式**：一行一行解码、一块一块喂给 `framer.FrameStreamer`，只留"每行解出多少字节"和帧索引；不保留全文、也不保留全部字节 |
| 帧 | 帧索引只有偏移/长度/校验状态（28.7 万帧约 3.6 MB）；帧字节**按需切**（`FrameSource`），最近用过的若干帧有个小缓存 |
| 编辑器 | 只装**当前页**（默认 2000 行），带 `◀ 上一页 / 下一页 / 第 N 页 / 跳到行` |
| 定位 | 点表格里的值 → 二分算出它在第几行 → **自动翻到那一页** → 按行内十六进制数字定位并反色选中（跨页就选到页尾） |
| 随机取字节 | `decode_bytes(字节偏移, 长度)` 只解涉及的那几行 → 取某一帧、导出某一段都是随机读取 |

于是内存和文件大小**脱钩**：128 MB 抓包私有提交 143 MB（大头是 PyQt6 自己），
命令行也一样 —— `cli.py --read-mb 0` 会走同一条路径，1 GB 日志也不用先读进内存。

### 表格：无上限 + 滑动窗口

三张"会很长"的表都不再有"最多多少帧/行"：

| 表格 | 行数 | 做法 |
|---|---|---|
| 帧列表 | **= 帧数**（例：287,482 行） | 只填视口附近的 ~600 行；滚到哪现算哪；行数初始铺 20,000，滚到底自动续（2 万 → 4 万 → 16 万 → 全量） |
| 数据表分析 | **= 行规则命中的帧数**（例：287,482 行） | 同上；统计仍按全部（或筛选后）帧算，与是否滚到无关 |
| 字段解析 | **= 帧数 × 字段数**（例：28.7 万 × 8 = 2,012,374 行） | 滚到哪就**解析哪一帧的字段**（带 4000 帧的解析缓存），不再预先解析前 N 帧 |

实现要点（`app/ui/table_base.py` 的虚拟行）：

* `begin_virtual(总行数, filler)`：表格对外是"完整行数"，内部只在窗口里放行数据；
* 远处已填的行会被释放，所以**内存不随滚动增长**；
* Qt 给每一行都要留元数据（200 万行 ≈ 144 MB），所以行数**按需扩容**：
  初始 2 万行，滚到接近末尾就翻倍，一路滚到底才铺满（导出/复制/定位不受影响，都按需取行）；
* 导出/复制走 `row_texts(row)` 按行现算，不再依赖"控件里有没有这一行"。

实测 128 MB / 28.7 万帧（私有提交内存）：解析完 **85 MB** → 帧列表滚到底 **118 MB** →
再开分析页 + 字段表、一路滚到底 **168 MB**；每帧点选 10 ~ 20 ms。

* 帧列表 / 字段表以外的显示上限：字节对照表最多 2048 字节（那是"字节数"，不是帧数）、
  列规则最多 256 列、分析页统计默认取前 50,000 帧（可用「行规则…」卡任意区间）；
* **帧数本身不设上限**：`分帧设置 → 最多分` 默认 `0 = 不限`，128 MB 抓包能一次分出 28.7 万帧；
  想快速预览超大文件时可设上限（达到上限会在日志里明确提示）；
* 后端不设限：筛选、进制视图、导出 JSON、命令行都按需取数据；
* 自动推断在 1.9 MB 数据上约 2 秒；解码走 `bytes.fromhex` 快速路径，1.9 MB 约 24 ms。

## 十五、流式计算与渲染（性能设计）

选项一变就"整包重算 + 整表重绘"是浪费，大文件还会卡住界面。这里的做法：

**1. 脏标记分级** —— 谁变了就从谁开始，下游复用缓存：

| 变化 | 级别 | 重算什么 |
|---|---|---|
| 输入数据 / 进制 / 字节序 | `DECODE` | 从解码开始全跑 |
| 分帧设置（帧头/帧长/校验/分隔符/跳过） | `FRAME` | 重新分帧 + 重算字段，输入字节复用 |
| 字段定义（偏移/类型/系数/表达式） | `FIELDS` | 只重算字段与表格行，分帧结果复用 |
| 列格式/列颜色/列换算函数 | 面板本地 | 只重绘那一列，不碰数据 |
| 帧筛选 | `RENDER` | 只重渲染，复用分帧与字段缓存（表格行数跟着筛选结果变） |

**2. 时间片推进 + 自适应片长** —— 主循环是个生成器（`app/pipeline.py`），
解码按行分片、分帧后按"帧 × 字段"估一个保守片长，每片实测耗时超过预算就 ×0.6、
远低于预算就 ×1.5，自动收敛到 4/8/12/20/40 ms（工具栏「切片」可调）。
**解析和渲染在同一个时间片里完成**：一块帧解析完立刻发信号给表格追加行，表是"长出来"的。

**3. 可抢占** —— 新请求（改参数、改输入）直接关掉旧生成器（generation 计数），不做无用功，
也不会重复渲染（自检里有"流式与同步结果一致"的用例）。

**4. 只算看得见的** —— 进制视图 / 位编辑器 / JSON 都改成**惰性**：切到那个页签才生成，
其它时候只是打脏标记。

**5. 悬停提示按需计算** —— 以前给每一格预生成 HTML 提示（12663 帧 × 8 字段 ≈ 每格一次格式化），
现在改在 `viewportEvent` 里悬停时才生成，省掉大量字符串与内存。

**6. 解码走 C 级快速路径** —— `bytes.fromhex` 直接吃空格分隔/连写的十六进制，
逐 token 的 Python 校验只做兜底：1.9 MB（200 万个片段）从 **944 ms → 24 ms**。

实测（`data/backward_sample.txt`，1975428 字节 / 12663 帧 / 8 字段）：

| 模式 | 首屏（第一批结果） | 最长一次界面停顿 | 跑完总耗时 | 时间片 |
|---|---|---|---|---|
| 同步（关掉流式） | 1510 ms | 1510 ms | 1510 ms | — |
| 流式 4 ms | 233 ms | 95 ms | 1462 ms | 216 |
| 流式 12 ms | **184 ms** | **76 ms** | 1278 ms | 74 |
| 流式 40 ms | 179 ms | 77 ms | 1090 ms | 19 |

即：**首屏快 8 倍、最长停顿短 20 倍**，总耗时基本不变（CPU 利用率反而更平稳，
不再有"一下占满一秒"的尖峰）。工具栏「流式渲染」可随时开关对比。

## 十七、扩展

* **加校验算法**：在 `app/checksum.py` 写 `def _xxx(data: bytes) -> int`，在 `ALGOS` 里登记
  `(key, 显示名, 字节数, 默认字节序)`，界面、试算、推断、导出自带。
* **加分帧方式**：在 `app/framer.py` 写 `_split_xxx(data, cfg, result)`，登记进 `MODE_ITEMS` 与
  `_DISPATCH`，再在 `app/ui/panels.py` 加参数页。
* **加字段类型**：在 `app/field_parser.py` 的 `parse_field` 加分支，并加进 `TYPE_ITEMS`。
* **加预设**：在 `app/presets.py` 里拼 `Preset(frame=..., fields=..., sample=...)`；
  大样本用 `sample_file="xxx.txt"` 从 `data/` 读前 N 行（见预设 ⑧）。
* **换主题**：只改 `app/ui/theme.py`（配色常量 + 样式表），界面代码不写死颜色。
